**Smappee EV 2026.11.0 — Service status and Marketplace preparation**

This release adds Smappee service-status sensors and prepares the integration
for Home Assistant's built-in Marketplace. It also improves Dashboard outage
recovery, charging-session handling, MQTT reconnection and control reliability.

**Smappee service status** — [#315](https://github.com/myny-git/smappee_ev/pull/315), [#327](https://github.com/myny-git/smappee_ev/pull/327)

- Adds a **Smappee Service Status** diagnostic device with problem sensors for
  services such as Dashboard, API, Cloud, Live data and EV Line. Off means OK;
  on means a reported problem or maintenance.
- Adds an **Active incidents** sensor with incident details in its attributes.
- Checks public service status every **15 minutes** with live MQTT data,
  increasing to **5 minutes** when a configured site has no connected MQTT source
  with a valid measurement received in the last five minutes. Heartbeats alone
  do not count. Normal polling resumes when live measurements return.
- Status requests run in the background with a timeout and do not delay charger
  monitoring. Failed initial requests recover automatically without a reload.
- Invalid or empty responses mark the status sensors unavailable and retry after
  five minutes. The last valid data is retained until recovery.
- Each account has separate status entities. Existing status registrations are
  migrated while preserving entity IDs and user customizations.

Thanks to @geertmeersman for contributing the initial service-status integration.

**Marketplace preparation**

- Updated installation instructions for **Settings -> Marketplace** on Home
  Assistant 2026.11 and newer, while retaining HACS instructions for older versions.
- Existing HACS installations migrate automatically when Home Assistant moves
  to Marketplace. There is no need to remove or configure Smappee EV again solely
  for this transition.
- Preserves the existing catalog entry, `hacs.json`, installation link and ZIP
  format. Fixes Probatio schema typing while keeping older runtime compatibility.

**Dashboard recovery and connection reliability**

- Fixes coordinator refresh handling during recovery probes and improves cleanup
  after failed or cancelled setup and recovery attempts.
- Adds recovery progress to diagnostics: status, attempt count, last attempt,
  next retry and error category, without response bodies or credentials.
- MQTT reconnect delays now reset only after subscriptions succeed, preventing
  rapid retries when the connection works but subscription setup fails.
- Cleans up status requests, timers and completed background tasks on unload.

**Charging sessions and control fixes**

- Final session checks are now tracked per connector. Repeated end-of-session
  messages do not postpone them, and another connector's activity cannot cancel
  them. The checks remain scheduled after 30 seconds, two minutes and five minutes.
- Unsupported charging-state and EVSE-status values now appear as unknown, with
  the original value available in `raw_status`, instead of causing invalid
  Home Assistant ENUM states.
- Partial REST responses no longer clear a previously known percentage limit.
- Successful cable-lock changes are protected against older Dashboard responses,
  including commands that confirm the current lock state.
- Numeric controls report API failures consistently and continue to reconcile
  commands whose outcome is uncertain.

**Documentation, compatibility and releases**

- Removes the CodeQL status/runtime import cycle and adds a regression guard.
- Updates device-registry cleanup with a fallback for older Home Assistant versions.
- Release ZIPs now use the actual release tag revision and require a matching
  manifest version, keeping the source and downloaded package consistent.
- Expands regression coverage for recovery, session deadlines, status failures,
  multiple accounts, registry migration and release packaging, and updates CI tooling.

**Upgrade notes**

- Restart Home Assistant after updating the integration.
- **Home Assistant 2026.11 is not required to use this integration release.**
  Keep using HACS on Home Assistant 2026.10 and older. On 2026.11 and newer, use
  Marketplace and accept its community-content notice if prompted.
- Existing accounts do not need to be removed or configured again.
- Automations using `charging_state` or `evse_status` should handle unknown values.
  Check the `raw_status` attribute when troubleshooting an unsupported status.
- Public Smappee service status is separate from your charger's charging state
  and MQTT connectivity.
